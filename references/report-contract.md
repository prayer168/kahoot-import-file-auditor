# 交付與追溯規格

預設交付一份批次摘要（回覆或 Markdown）與一份獨立的 `Kahoot_逐題查核報告.xlsx`。批次可合併審查報告，但不同來源檔不可合併成單一匯入測驗。大量題目用篩選與凍結欄位協助閱讀，不省略各題。

## 報告工作表

### 查核摘要

包含輸入檔清單、已確認與推估的教學背景、各檔讀取／審查狀態、擷取題數、完成題數、未完成題數、A／B／C 問題數及各級受影響題數、待確認事項。列出內容品質、官方格式規則、實際上傳驗證三種獨立結論與整體配置建議。程式無錯誤不等於內容審查完成。

### 逐題審查

每題一列，至少包含：

- 題目 ID、來源檔或 ZIP 成員、工作表、Excel 列號、原題號、確認／推估的題型。
- 原題幹、原選項 1–4、原答案編號與對應文字、原時間。
- 核定答案編號與文字、各選項正誤理由、答案證據狀態。
- 課綱對應及依據、學習階段／進度適切性、素養特徵、情境必要性、認知要求。
- 選項 1–4 各自的迷思或錯誤推理／誘答分析（正解標不適用）；來源支持或推估的區分。
- 年段用詞及敘述、圖片／資料／實驗條件、時間配置與格式問題。
- 問題等級、結論、問題說明、具體建議題幹與選項、建議答案、是否改變原答案、來源 ID、待確認資料、完成狀態。

如欄位過寬，將選項分析移至單獨的長表（題目 ID＋選項編號），以一對多關聯；不得合併成無法追溯的摘要。原始欄位與建議欄位清楚區別，不以色彩作唯一標示。

### 查證來源

按 `evidence.md` 的格式記錄證據；只列實際開啟且支持結論的資料。

### 修改紀錄（有修改或複審才建立）

記錄題目 ID、原位置、新位置、修改欄位、前值、後值、原因、受影響答案及複審結果。需刪除題目時保留紀錄及理由，不為消除問題而悄悄刪題。

## 建議改寫與修正版

只改必要部分並保留學習目標。新增迷思選項須重新驗證其科學錯誤與可排除性。修正內容改變正解或排列時，同步更新答案編號、答案文字與解析。

修正版必須使用當次官方範本，不在匯入檔增加審查欄位或教師解析頁。範本範例題須辨認後移除，避免混入正式題庫。不保留會使題目依賴未交付素材的「見圖」敘述。

## 交付驗證

1. 所有輸入檔均出現在清單；每個來源題有唯一 ID，擷取、完成、待審題數可核對。
2. 所有 A 級與未決項目出現在摘要。未審查不計為通過；不適用有理由。
3. 改寫後每個選項重新求解，核定答案編號對應正確文字；題號可追溯。
4. 重新讀取已儲存的報告及修正版，核對題數、中文、來源位置、選項與答案。原檔內容未變。
5. 檢閱報告的代表性長文列及各頁呈現，文字換行、列高與欄寬可閱讀，不讓截斷隱藏問題。
6. 僅交付完成品與必要限制；程式中間 JSON 不冒充已完成審查報告。
